# Pidge 1.0 — Agent-Grade Release Design

**Date:** 2026-07-07
**Status:** Approved scope (A+B+C+D+E, version 1.0.0); architecture approved (evolve-in-place, single `execute()` seam)
**Goal:** Make pidge the most reliable, controllable, and token-efficient tool an AI agent can hold — without changing what it already does well.

## Scope decided with Kristofer

- **A. Reliability layer** — retry/backoff on every Graph call, cursor pagination, `$batch`, exit-code taxonomy, structured error envelope.
- **B. watch/delta** — Graph delta queries; one-shot `mail delta --cursor` and streaming `pidge watch` (JSONL).
- **C. Guardrails + dry-run** — user-enforced policy per action class; `--dry-run` on mutating commands.
- **D. Threads + token-thrift** — conversation grouping, `mail thread`, `--fields`/`--max-chars`.
- **E. Housekeeping** — docs drift (browser PKCE not device code; calendar shipped), dep bumps, search date-sort, command-layer tests.
- **Version 1.0.0.** No MCP server (explicitly out of scope; the emitted skill remains the agent surface). No new Graph domains (tasks/contacts/presence saved for later).

## Architecture

Evolve in place. All Graph traffic already flows through `GraphClient` per-op methods; add one private choke point:

```rust
async fn execute(&self, build: impl Fn(&reqwest::Client, &str /*token*/) -> RequestBuilder)
    -> Result<Response, ClientError>
```

- Owns: token fetch, send, 429/503/504 retry with `Retry-After` (fallback exponential + jitter, max 4 attempts), terminal `ClientError::Throttled`.
- Every per-op method routes through it; existing wiremock tests keep passing; new wiremock tests cover retry behavior.
- Guardrails live in `pidge-core::config` (types + evaluation) and are enforced in the command layer of `crates/pidge` (the only layer that knows an action's class and has a TTY).
- New `pidge-client` modules: `graph/batch.rs` ($batch), `graph/delta.rs` (delta queries). New `pidge` modules: `commands/watch.rs`, `commands/mail_thread.rs`; `output/envelope.rs` (error envelope + exit codes).

## A — Reliability layer

### Retry/backoff
- Retry on 429/503/504; honor `Retry-After` seconds header; else backoff 1s·2^attempt + 0–250ms jitter; 4 attempts max.
- Existing bulk-op retry code (mail_actions/mail_delete) collapses onto `execute()`; bulk concurrency (4 inflight) stays.
- Terminal throttle → `ClientError::Throttled { retry_after: Option<u64> }` → exit 5.

### Cursor pagination
- `mail list/search` and `calendar list` gain `--cursor <token>`; JSON output becomes an object when cursoring: `{"items": [...], "next_cursor": "..." | null}` (plain array retained when `--cursor` unused and no next page — backward-friendly; skill documents the shape).
- Cursor = base64(JSON `{v:1, kind:"mail-list", per_account: {email: nextLink|done}}`). Opaque; versioned; invalid → exit 2 with `bad_cursor` code.
- Merges across accounts stay time-ordered: each page pull takes the newest head among per-account buffers (streaming k-way merge), so deep paging neither skips nor duplicates.
- `-p/--page` stays for humans (unchanged semantics).

### $batch
- `graph/batch.rs`: POST `/v1.0/$batch`, ≤20 sub-requests, maps sub-responses back; per-sub-request 429 honored via `retryAfter` in body → re-batch the failed subset.
- Applied to: bulk mark-read/move/delete/categorize (today N sequential calls with concurrency), and multi-account single-shot reads where all accounts hit the same endpoint shape (mail list first page, calendar list window). Single-op commands unchanged.

### Exit codes + error envelope
- Taxonomy: `0` ok · `1` unexpected · `2` usage/bad input (incl. bad cursor, ambiguous fragment *pattern* errors are 4) · `3` auth expired/missing · `4` not found or ambiguous fragment · `5` throttled · `6` guardrail denied.
- Implementation: `PidgeError` wrapper in the CLI mapping `ClientError`/`CoreError` → code; `main` matches and `process::exit(code)`.
- With `--json`, errors emit one line to stderr: `{"error": {"code": "auth_expired|not_found|ambiguous|throttled|guardrail_denied|usage|graph|unexpected", "message": "...", "hint": "...", "account": "...?", "retry_after": n?}}`. Human format unchanged otherwise.

## B — watch/delta

### `pidge mail delta`
- `pidge mail delta [--folder inbox] [--cursor <c>] [--account <email>|all]`
- No cursor → bootstrap: performs the initial delta round(s) to the current state and prints `{"events": [], "next_cursor": "..."}` (state established, nothing replayed). `--full` bootstrap additionally emits current messages as `created` events (agent building an index).
- With cursor → emits changes since: `{"events": [{"type": "created|updated|deleted", "message": {MessageOut…}} …], "next_cursor": "..."}`. Deleted events carry `{id, graph_id, account}` only.
- Cursor wraps per-account `deltaLink`s (same envelope as pagination cursors, `kind:"mail-delta"`). Graph expired-delta (410) → error `delta_expired`, hint "re-bootstrap without --cursor", exit 2.
- Folder scope: delta is per-folder (Graph limitation); default inbox.

### `pidge calendar delta`
- Same shape over `/me/calendarView/delta` with a rolling window (`--from/--to`, default today→+14d). Window is baked into the cursor.

### `pidge watch`
- `pidge watch [--mail] [--calendar] [--interval 60] [--account …]` (no flags = both, 60s).
- Loop: delta poll each interval; each event printed as **one JSONL line** to stdout: `{"stream": "mail|calendar", "type": "...", "at": "...", "message"/"event": {...}}`. Errors → JSONL `{"stream":"watch","type":"error",...}` and keep looping (throttle honors retry-after); Ctrl-C exits 0.
- State kept in memory (cursors); `--state-file <path>` persists cursors so a restarted watch resumes (agents running pidge under a supervisor).

## C — Guardrails + dry-run

### Policy
- `config.yaml`:
  ```yaml
  guardrails:
    send: allow      # send/reply/forward/drafts send
    delete: confirm  # mail delete, rmdir, calendar delete
    cancel: allow    # calendar cancel (organizer notices)
    rsvp: allow
    bulk: confirm    # any --from/--older-than bulk mutation
    unsubscribe: allow
  ```
- Values: `allow` (today's behavior) · `confirm` (interactive TTY confirmation required **even with `-y`**; non-TTY → exit 6, code `guardrail_confirm_required`, hint "ask the user to run interactively or relax guardrails") · `deny` (always exit 6, `guardrail_denied`).
- Default when absent: all `allow` — zero behavior change until the user opts in. Managed via existing `pidge config set guardrails.send confirm` (dotted keys already work); `pidge config show` displays them.
- Evaluation: `GuardrailAction` enum + `Config::guardrail(action) -> GuardrailMode` in pidge-core; enforced at the top of each mutating command handler.

### Dry-run
- `--dry-run` on every mutating command (send/reply/forward/drafts send/delete/archive/move/mkdir/rmdir/unsubscribe/categorize set/clear, calendar new/edit/move-time/duplicate/delete/cancel/move/rsvp, bulk variants).
- Prints a human summary of exactly what would happen (recipients, subject, body first 200 chars, attachment names / event title+time+attendees / target folder / affected message count for bulk — bulk dry-run performs the *read* to enumerate matches) and exits 0 without mutating. With `--json`: `{"dry_run": true, "action": "...", "detail": {...}}`.
- Guardrails are evaluated before dry-run reporting (a denied action reports `would be denied by guardrails`, still exit 0 — dry-run never fails on policy, it reveals it).

## D — Threads + token-thrift

- `MessageOut` gains `conversation_id` (from Graph `conversationId`).
- `pidge mail thread <frag>`: resolves the fragment, fetches all messages with the same `conversationId` (`/me/messages?$filter=conversationId eq '…'&$orderby=receivedDateTime`), renders chronologically (compact per-message header + body text). `--json` → array of MessageOut with `body_text`. Cross-account: thread fetched from the account owning the fragment.
- `pidge mail list --threads`: groups the page by conversation, shows latest message + `(N msgs)` count; JSON: `{"conversation_id": ..., "count": n, "latest": {MessageOut}}`.
- Token-thrift on all `--json` list/show outputs: `--fields id,subject,from` (top-level field projection, unknown field → usage error listing valid names) and `--max-chars N` (truncate `body_text`/`preview` with a `…[truncated N chars]` suffix so agents know).
