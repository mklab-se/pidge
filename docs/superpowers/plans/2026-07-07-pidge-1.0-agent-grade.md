# Pidge 1.0 Agent-Grade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship pidge 1.0.0: retry/backoff on every Graph call, cursor pagination, $batch, exit-code taxonomy + error envelope, mail/calendar delta + watch, guardrails + dry-run, threads + token-thrift, housekeeping.

**Architecture:** Evolve in place. One `execute()` retry seam inside `GraphClient`; new `graph/{batch,delta}.rs`; guardrail types in pidge-core, enforcement in command handlers; envelope/exit codes in a new `pidge` module. Existing wiremock tests must keep passing.

**Tech Stack:** Rust 2024 (MSRV 1.85), reqwest 0.12/rustls, wiremock 0.6, serde, clap 4, tokio.

**Spec:** `docs/superpowers/specs/2026-07-07-pidge-1.0-agent-grade-design.md` (authoritative for all semantics; this plan indexes it).

## Global Constraints
- Gates per CLAUDE.md: `cargo fmt --all -- --check && cargo clippy --workspace -- -D warnings && cargo test --workspace` (also `--all-targets` clippy clean); commit per task.
- Live testing against Kristofer's real accounts: **read-only + reversible only** — no real mail sent, no calendar events mutated; drafts may be created then deleted; mark-read/unread allowed (reversible).
- Default guardrails = all `allow` (zero behavior change until user opts in).
- JSON shapes documented in SKILL.md must match implementation exactly.

### Task 1: `execute()` retry seam
**Files:** Modify `crates/pidge-client/src/graph/mod.rs` (add `execute`), `crates/pidge-client/src/error.rs` (add `Throttled { retry_after: Option<u64> }`); route all per-op methods in `graph/{mail,events,calendars,me}.rs` through it. Test: wiremock in `graph/mod.rs` tests.
**Interfaces (produces):** `async fn execute<F>(&self, account: &str, build: F) -> Result<reqwest::Response, ClientError> where F: Fn(&reqwest::Client, &str) -> reqwest::RequestBuilder` — token fetch + send + retry on 429/503/504 honoring `Retry-After` (fallback 1s·2^n + 0–250ms jitter, 4 attempts) → `Throttled` after exhaustion. Non-retryable statuses pass through.
- [ ] Failing wiremock tests: (a) 429 with `Retry-After: 0` twice then 200 → succeeds, 3 requests observed; (b) persistent 429 → `Err(Throttled)`, 4 requests; (c) 400 → immediate Graph error, 1 request.
- [ ] Implement; port every per-op method (mechanical: replace token+send pairs); collapse the bespoke bulk retry in `crates/pidge/src/commands/{mail_actions,mail_delete}.rs` onto plain client calls (keep 4-inflight concurrency).
- [ ] Full suite green → commit `feat(client): centralized retry/backoff on every Graph call`.

Guardrail errors are a typed `GuardrailError` (Task 6) downcast here.
- [ ] Failing unit tests for `classify`: `ClientError::SessionExpired` → (3, code `auth_expired`, hint contains "pidge account add"); `Throttled{Some(30)}` → (5, retry_after 30); `CacheLookup` ambiguous/not-found errors (existing anyhow messages — introduce typed `FragmentError { NotFound, Ambiguous(Vec<String>) }` in pidge-core cache and use it) → 4; unknown → 1.
- [ ] Wire `main`; `--json` errors print envelope as single stderr line.
- [ ] Commit `feat: differentiated exit codes + structured error envelope`.

### Task 6: Guardrails + dry-run
**Files:** Modify `crates/pidge-core/src/config.rs` (GuardrailAction/GuardrailMode + `guardrail()` lookup + serde); create `crates/pidge/src/guardrail.rs` (enforcement helper + `GuardrailError`); add `--dry-run` to every mutating command in `cli.rs` + handlers.
**Interfaces (produces):** `enum GuardrailAction { Send, Delete, Cancel, Rsvp, Bulk, Unsubscribe }`; `enum GuardrailMode { Allow, Confirm, Deny }`; `Config::guardrail(a: GuardrailAction) -> GuardrailMode` (absent → Allow); CLI helper `enforce(config, action, yes_flag, json) -> Result<(), GuardrailError>` — Confirm + TTY → inquire prompt (overrides `-y`); Confirm + non-TTY → `GuardrailError::ConfirmRequired`; Deny → `GuardrailError::Denied` (both → exit 6 via Task 2). Dry-run: `DryRunReport { action: &'static str, detail: serde_json::Value }` printed human or `{"dry_run":true,...}`; evaluated after guardrail check but never fails on policy (reports would-be-denied, exit 0).
